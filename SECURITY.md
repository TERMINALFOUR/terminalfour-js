# Security Policy

## Reporting a Vulnerability

**Report privately. Do not open a public issue, discussion, or merge request.**

Email **terminalfour-sdk@terminalfour.com** with:

- What the vulnerability is and the impact you believe it has.
- The affected version(s).
- Steps to reproduce.
- A minimal proof of concept, only if needed to demonstrate the issue safely.

Do not include live customer data, personal data, credentials, tokens, private
keys, or exploit code beyond the minimum needed. If you send any of these by
accident, tell us so we can handle it correctly.

## What to Expect

Once you report a vulnerability, we will:

- Acknowledge that we have received your report.
- Assess the report and confirm whether we accept it.
- Work on a fix and keep you informed of progress.
- Release the fix and, if you want it, credit you in the release notes.

Remediation follows the Terminalfour Penetration Testing and Vulnerability
Management Policy. Customers and partners can request a copy at the address
above.

There is no bug bounty for this project.

## Supported Versions

Only the latest released version receives security fixes.

## Safe Harbour

We will not pursue or support legal action against you for security research
carried out in good faith under this policy, provided you:

- Only test against systems and data you own or are authorised to test.
- Do not access, modify, exfiltrate, or destroy data belonging to others.
- Do not degrade or disrupt services.
- Give us a reasonable opportunity to remediate before disclosing publicly.

If in doubt about whether an action is in scope, ask us first.
